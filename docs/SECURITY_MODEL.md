# 安全模型

本说明介绍应用的设计边界，不能替代对当前实现、依赖和运行环境的审查。OpenAster 是实验性个人项目，不保证没有漏洞。

## 需要保护的内容

项目文件、会话记录、模型凭据、审批决定和模型请求中的数据都属于需要保护的内容。浏览器界面、本地服务、工具进程和外部模型之间的访问边界应分别检查。

## 模型与外部数据

模型输出、文件、网页及 Skills 内容都是不可信输入。它们可以提供任务信息，但不能自行授予新权限、修改工具策略或免除审批。

配置外部模型后，参与请求的消息、图片、技能内容与文件片段可能离开本机。“本地工作台”不等于所有推理和数据处理均在本地。是否可以发送这些内容，由使用者的数据授权和服务条款决定。

## 文件与命令

文件工具通过明确的工作区边界、路径和参数检查降低误访问风险。对写入、覆盖等操作，审批应展示具体对象和变更，而不是宽泛地批准整个任务。

Shell 命令具有不同的风险：命令进程受操作系统用户权限约束，可能启动程序、访问网络或产生其他副作用。界面审批、命令预览和应用层限制不等同于进程沙箱，不应据此认为任意获批命令均安全。

取消是停止后续工作的机制，不是通用回滚。已经产生的修改或外部请求可能仍然有效。

## 界面与协议

Markdown、代码块、图片和工具结果都需要作为不可信内容处理；解析与渲染应限制输入范围，避免把模型内容直接变成可执行界面代码。

模型适配器负责协议映射与请求边界。某个服务的一次成功请求不能证明所有端点、重定向、流式事件、错误响应和工具参数都已兼容。

## 桌面与移动网关

桌面封装包含浏览器渲染进程与系统集成边界；平台功能不应向页面暴露无限制的系统接口。

本机访问和远程网关应分别配置。移动连接需要可信 HTTPS、明确认证和受控访问范围；不要把开发服务直接公开，也不要通过忽略证书错误来满足连接要求。

## 凭据、记录与分享

凭据应通过应用支持的配置入口管理，不进入源码或公开示例。不同运行方式和操作系统的凭据保存能力可能不同，不能把某个平台的保护方式推广到所有平台。

错误信息、日志、备份、截图和导出记录都可能包含敏感内容。分享前进行检查与脱敏；用户同意测试某个账号不等于同意公开其连接信息。企业管理的文件还应遵循组织批准的导出流程。

发现潜在漏洞时，按[安全策略](../SECURITY.md)报告，并仅在获准的测试环境中复现。
