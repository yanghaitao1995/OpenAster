# 备份与恢复

备份可能包含敏感会话、图片消息和工作区内容，应视为用户数据，不属于可公开的项目源码。只备份自己拥有或获准处理的数据；受组织管理的文件仍需遵循其正式导出要求。

## 使用命令行

先关闭使用源数据目录的所有 OpenAster 实例，并确认界面或启动配置显示的实际数据目录。查看当前工具用法：

```sh
node scripts/backup.mjs --help
```

创建备份：

```text
node scripts/backup.mjs backup --data-dir ABS --output ABS [--workspace ABS]
```

将 `ABS` 替换为相应的绝对路径，路径含空格时使用引号。方括号表示可选参数，不应原样输入。未指定工作区时，工具使用数据目录下的 `workspace`。输出文件必须尚不存在，父目录需要已存在。

恢复到一个尚不存在的新数据目录：

```text
node scripts/backup.mjs restore --input ABS --data-dir ABS
```

不要把恢复目标指向现有数据目录。失败时先阅读错误码并保留原备份，不要为了绕过检查而手工删除备份中的校验信息。

## 范围与限制

工具输出可能含敏感内容的明文 JSON，不是加密保险箱。密钥、环境变量绑定和凭据库不随备份复制；不要因此认为其他会话或文件内容也已脱敏。

工作区备份支持受限的普通 UTF-8 文本和目录，遇到不允许的链接、二进制、凭据文件或超限内容会拒绝。它不是任意项目的完整磁盘镜像，也不替代针对重要文件的独立备份方案。

恢复不会自动调用模型：外部模型连接会停用，活动任务取消，历史待审批写入拒绝。恢复后应核对数据与工作区，再单独配置模型凭据和决定后续操作。

不要把备份上传到 Issue、公共仓库或未经授权的服务。确认恢复有效后，仍应按自己的数据保留规则管理原件与备份。
