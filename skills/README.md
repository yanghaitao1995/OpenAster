# OpenAster Skills

源码运行时技能保存在应用根目录的 `./skills/<id>/SKILL.md`。桌面应用在当前项目的 `./skills` 不存在时复制一份内置技能，之后只读取这个目录；已经存在的目录（包括空目录）完全保留，不合并或覆盖。新增技能后重新打开技能页面或开始新任务即可重新发现；已有任务按当前运行捕获的目录工作。

```markdown
---
name: 我的技能
description: 描述这个技能处理的具体任务，以及什么时候应该使用。
icon: code
---

这里放完整的工作说明。需要额外材料时引用 [检查清单](references/checklist.md)。
```

`id` 取文件夹名，允许小写英文字母、数字、`_`、`-`，长度 1–64。`name` 和 `description` 必填，支持普通文字、单引号、JSON 双引号、`>` 折叠文本与 `|` 多行文本。可选 `icon` 使用内置图标名。其他元数据不改变任何工具权限。

开始任务时模型仅获得名称、用途与 ID。需要使用技能时，模型调用 `load_skill` 读取正文；需要某个引用资源时再调用 `read_skill_resource`。引用资源按该技能目录解析，不读取其他技能、父目录、绝对路径、符号链接、硬链接或已知敏感文件。单份正文或资源最多 256 KiB，元数据最多 8 KiB，最多 128 个技能。

技能文件是用户可编辑的指导材料，不是系统权限。修改文件和运行 shell 仍遵守当前任务的权限与审批；技能引用的脚本不会自动执行。把不可信技能当作代码审阅后再使用，不要在技能文件中写入访问令牌或私人凭据。

旧版六个内置技能的 ID 保持不变，已保存的选择和草稿可以继续使用。旧版写死在 JavaScript 中的完整提示词已迁入这些文件；模型不再提前收到所有正文。代码技能的说明也改为可以在授权后运行命令，并要求以实际工具结果报告验证情况。

桌面应用的技能在项目目录中可直接编辑。安装包内的技能只作为首次初始化来源，不会通过模型修改安装目录；同一个项目已有的技能也不会在升级时被内置版本覆盖。源码运行时直接编辑此目录即可。

本目录的示例由 OpenAster 原创，按仓库 Apache-2.0 许可证提供。
